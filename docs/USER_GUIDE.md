# Руководство пользователя BotCRM

BotCRM — единое рабочее место для команды, которая управляет самописными ботами, общается с людьми и ведёт их до результата: продажи, оплаты, записи, поддержки или другого финального состояния.

## 1. Роли

| Роль | Для кого | Основные возможности |
|---|---|---|
| Владелец | собственник системы | полный доступ; только он может назначить другого владельца и управлять учётной записью другого владельца |
| Администратор | технический/операционный администратор | пользователи ниже владельца, команды, токены, каналы, CRM, автоматизации и рассылки |
| Руководитель | руководитель продаж/поддержки | работа с клиентами, настройка воронок, сегменты, рассылки, автоматизации, отчёты и контроль операторов |
| Оператор | менеджер или сотрудник поддержки | переписка, контакты, сделки, заметки и задачи; административные настройки доступны только для чтения либо скрыты |
| Сервисный аккаунт | самописный бот или worker | только специально разрешённые API-операции, без входа в панель |

### Точная матрица доступа

| Действие | Владелец | Администратор | Руководитель | Оператор |
|---|:---:|:---:|:---:|:---:|
| Смотреть диалоги, контакты, сделки и аналитику | ✓ | ✓ | ✓ | ✓ |
| Отвечать, забирать/возвращать диалог, менять контакт и сделку | ✓ | ✓ | ✓ | ✓ |
| Создавать и настраивать воронки и стадии | ✓ | ✓ | ✓ | — |
| Импортировать/экспортировать и объединять контакты | ✓ | ✓ | ✓ | — |
| Обезличивать контакт | ✓ | ✓ | — | — |
| Создавать сегменты, рассылки и смотреть получателей | ✓ | ✓ | ✓ | — |
| Создавать, тестировать и включать автоматизации | ✓ | ✓ | ✓ | — |
| Проверять состояние подключения канала | ✓ | ✓ | ✓ | — |
| Подключать, изменять и удалять ботов/каналы | ✓ | ✓ | — | — |
| Управлять пользователями, командами и сервисными токенами | ✓ | ✓ | — | — |
| Назначать роль владельца и изменять другого владельца | ✓ | — | — | — |

Инварианты безопасности:

- пользователь не может отключить себя или изменить собственную роль через управление командой;
- администратор не может отключить владельца, понизить его или назначить нового владельца;
- в рабочем пространстве всегда должен оставаться хотя бы один активный владелец;
- скрытие кнопки в интерфейсе не является защитой: API повторно проверяет роль на каждом запросе;
- сервисный токен не наследует права владельца и принимается только на явно разрешённых endpoint.
## 2. Диалоги

Раздел объединяет переписку из всех подключённых ботов.

Можно:

- переключаться между людьми и видеть полную историю;
- фильтровать по каналу, боту, режиму и непрочитанным;
- искать по имени и тексту;
- отправлять текст и вложения;
- использовать эмодзи и быстрые шаблоны;
- оставлять внутренние заметки и задачи;
- редактировать контакт, теги и переменные;
- менять стадию сделки прямо из профиля;
- забирать управление у бота и возвращать его.

### Пример: бот передал горячего клиента

1. Откройте «Непрочитанные».
2. Выберите диалог.
3. Нажмите «Перехватить». Состояние станет `HUMAN`, совместимый бот перестанет отвечать.
4. Посмотрите `lead_score`, источник и историю.
5. Ответьте человеку и создайте задачу «Позвонить завтра».
6. Передвиньте сделку в «Предложение».
7. Нажмите «Вернуть боту», если дальнейшее сопровождение снова автоматическое.

Что это даёт: клиент не получает два параллельных ответа, а команда не теряет договорённости.

### Режимы управления

- `BOT` — входящие события передаются боту;
- `HUMAN` — отвечает оператор, совместимый бот заблокирован;
- `PAUSED` — диалог остановлен, автоматический ответ не выполняется.

## 3. Контакты

Контакт — человек или компания, а не отдельный чат. У одного контакта могут быть Telegram, VK, WhatsApp, Avito и Custom API идентификаторы.

В карточке доступны:

- имя, телефон, email и город;
- подтверждённые идентификаторы каналов;
- теги;
- произвольные переменные бота;
- статус согласия на рассылки;
- все диалоги и сделки;
- заметки, задачи и аудит.

### Пример: сегментация лидов

Бот записывает поля:

```json
{
  "lead_score": 84,
  "plan": "team",
  "payment_status": "waiting"
}
```

Оператор добавляет тег `горячий`. Руководитель создаёт сегмент: `lead_score >= 70 AND payment_status = waiting`. Этот сегмент затем используется в рассылке или отчёте.

### Массовые действия

Отметьте контакты чекбоксами, чтобы:

- добавить общий тег;
- разрешить рассылки при зафиксированном согласии;
- отметить отписку;
- экспортировать данные для внешней обработки.

Не назначайте `GRANTED`, если фактического согласия на сообщения нет.

## 4. Воронки и сделки

Воронка показывает, на каком этапе находится каждый контакт.

Можно:

- создать несколько воронок;
- добавить, переименовать, перекрасить и переставить стадии;
- назначить выигранные и проигранные финальные стадии;
- создавать и редактировать сделки;
- перетаскивать карточки мышью;
- искать по названию, боту и тегам;
- фильтровать по сумме и тегу.

### Пример воронки продаж

`Новая заявка → Квалификация → Предложение → Счёт → Оплачено`

Если пользователь нажал в боте «Получить счёт», автоматизация переносит сделку в «Счёт». Оператор видит карточку, проверяет сумму и связывается с клиентом. После оплаты CRM переносит её в «Оплачено».

Что это даёт: руководитель видит объём работы, сумму в каждой стадии и места, где клиенты чаще всего останавливаются.

## 5. Сегменты

Сегмент — сохранённый динамический фильтр. Контакты входят и выходят из него автоматически при изменении данных.

Доступны условия по:

- имени, телефону, email, городу;
- каналу и тегу;
- стадии сделки;
- пользовательским переменным;
- последней активности.

Поддерживаются `AND` и `OR`, сравнение, наличие значения, числовые границы.

### Пример

«Telegram-пользователи из Омска с `lead_score >= 80`, которые не отписались» — аудитория для персонального предложения менеджера.

## 6. Рассылки

Перед запуском система показывает точный предварительный расчёт аудитории и исключения.

Порядок работы:

1. Нажмите «Новая рассылка».
2. Выберите канал и сегмент.
3. Напишите отдельный подходящий текст.
4. Посмотрите список получателей.
5. Выполните тестовую отправку.
6. Сохраните черновик или назначьте время.
7. Запустите, поставьте на паузу или отмените.
8. Откройте результаты каждого получателя.

Метрики: аудитория, отправлено, доставлено, прочитано, ошибка и результат обработки.

### Пример безопасной рассылки

Сегмент: клиенты с тегом `вебинар`, канал Telegram, согласие `GRANTED`. Текст сообщает о переносе времени и предлагает ответить на сообщение. Отписавшиеся и недоступные автоматически исключаются.

Что это даёт: большая аудитория обрабатывается очередью без превышения лимита канала, а ошибки не теряются.

## 7. Автоматизации

Правило имеет вид «событие → условия → действия».

Примеры событий:

- получено/отправлено сообщение;
- создан или обновлён контакт;
- создана или перемещена сделка;
- нажата кнопка бота;
- нет активности;
- рассылка доставлена или завершилась ошибкой.

Примеры действий:

- изменить поле или тег;
- переместить сделку;
- назначить оператора;
- создать задачу;
- изменить режим диалога;
- отправить сообщение;
- вызвать подписанный webhook;
- добавить контакт в suppression list.

### Пример: лид просит менеджера

- событие: `message.received`;
- условие: текст содержит «менеджер»;
- действия: тег `нужен оператор`, режим `HUMAN`, задача «Ответить в течение 5 минут».

Перед включением запустите тест правила на выбранном контакте. Журнал показывает каждый запуск, действия и ошибки. Защита от циклов ограничивает повторные срабатывания.

## 8. Боты и каналы

Раздел хранит подключения Telegram, VK, WhatsApp Cloud API, Avito и generic REST.

Для каждого подключения видны:

- режим Gateway или Mirror;
- состояние подключения;
- адрес webhook;
- время последней проверки;
- ошибка и возможности канала;
- число настроенных секретных полей.

Секреты после сохранения нельзя посмотреть — только заменить.

### Gateway или Mirror

- Gateway выбирают для нового бота: webhook канала принадлежит BotCRM.
- Mirror выбирают для уже работающего бота: он копирует события в BotCRM через SDK/API.

Подробности — в [DEVELOPER_GUIDE.md](DEVELOPER_GUIDE.md).

## 9. Аналитика

Доступны периоды 7, 30 и 90 дней:

- новые диалоги;
- конверсия в оплату;
- первый ответ;
- выручка по выигранным сделкам;
- динамика диалогов и продаж;
- распределение по каналам;
- конверсия по стадиям;
- эффективность ботов.

Пример решения: если на стадии «Предложение» много сделок и растёт время ответа, руководитель перераспределяет операторов или создаёт автоматическую задачу.

## 10. Настройки и безопасность

Владелец и администратор могут:

- создавать учётные записи участников и отключать сотрудников ниже владельца;
- назначать роли в пределах своей политики: администратор — до администратора, владелец — включая владельца;
- собирать операторов в команды;
- создавать отдельные сервисные токены для ботов;
- отзывать сервисные токены;
- управлять собственными сессиями и включать TOTP 2FA.

Сейчас это локальное создание учётной записи: администратор задаёт временный пароль и передаёт его сотруднику безопасным способом. Автоматической email-ссылки-приглашения пока нет. После первого входа сотруднику следует получить собственный пароль и включить 2FA; перед публичным запуском рекомендуется добавить одноразовые приглашения с обязательной сменой пароля.

Особо защищены владельцы: администратор видит владельца в списке, но переключатель и список его роли недоступны. Сам владелец также не может случайно отключить или понизить себя через эту форму.
Рекомендации:

- один токен на одну интеграцию и окружение;
- не передавать токены в чатах и скриншотах;
- включить 2FA владельцу и администраторам;
- отключать ушедших сотрудников сразу;
- регулярно смотреть ошибки каналов и аудит.

## 11. Ежедневный сценарий оператора

1. Откройте непрочитанные диалоги.
2. Заберите те, где нужен человек.
3. Обновите поля и стадию.
4. Зафиксируйте договорённость заметкой.
5. Создайте следующую задачу.
6. Верните управление боту там, где это безопасно.

## 12. Сценарий руководителя

1. Проверьте просроченные задачи и диалоги у операторов.
2. Посмотрите сумму и время в стадиях.
3. Проверьте ошибки рассылок и подключений.
4. Изучите журнал автоматизаций.
5. Сравните каналы и конверсию в аналитике.

## 13. Импорт, экспорт и удаление

- Контакты импортируются из CSV/JSON.
- Экспорт позволяет забрать данные без зависимости от интерфейса.
- Объединение устраняет подтверждённые дубли.
- Обезличивание удаляет персональные поля, сохраняя допустимую техническую целостность истории.

Перед массовым импортом проверьте 5–10 строк на тестовой установке. Перед обезличиванием убедитесь, что выбран правильный контакт.

## Реестр переменных ботов

BotCRM не требует фиксированных названий переменных. `lead_score`, `intent` и `requested_plan` в примерах — обычные поля тестового бота, а не системные ключи.

- Когда бот впервые присылает новый ключ внутри `attributes`, платформа автоматически регистрирует его и определяет начальный тип.
- В разделе «Контакты» администратор открывает «Переменные», задаёт понятное команде название, проверяет тип и указывает источник истины: бот или BotCRM.
- Поля с признаком «Использовать в фильтрах» автоматически появляются в таблице контактов, сегментах и условиях автоматизаций.
- Ключ API после создания не меняется: иначе старый бот и сохранённые правила перестали бы находить значение. Отображаемое название менять можно.
- Удаление описания поля не стирает значения контактов. Это защищает данные от случайной потери.

Пример: ваш бот прислал `attributes: { "risk_level": "high" }`. В реестре появится `risk_level` типа «Строка». Администратор переименует его для интерфейса в «Риск ухода», после чего оператор сможет выбрать «Риск ухода» в сегменте или автоматизации, не вспоминая технический ключ.
