# Автоответы по ключевым словам

Раздел **«Автоответы»** позволяет редактору менять выдачу контента без доступа к коду и без нового релиза бота. Для пользователя и для подключённого бота единственной точкой входа является BotCRM. Directus остаётся внутренним хранилищем и наружу ботам не выдаётся.

## Что можно настроить

- фразу и режим совпадения: точно, содержит фразу, любое или все слова;
- приоритет и включение правила;
- черновик или опубликованный ответ;
- несколько текстовых и медиаблоков в нужном порядке;
- фото, видео, аудио и документы с Яндекс Диска;
- кнопки-команды и кнопки-ссылки;
- короткий fallback или полноценный готовый ответ, если правило не найдено.

BotCRM не отвечает пользователю сам. Сообщение по-прежнему обрабатывает конкретный бот, но опубликованный контент он читает через runtime API BotCRM по персональному токену. Поэтому не возникает двух параллельных обработчиков одного сообщения.

## Граница между системами

| Система | Отвечает за |
|---|---|
| BotCRM | реестр ботов, интерфейс, роли, изоляцию и единственный API контента для ботов |
| Внутренний Directus | физическое хранение правил и состояния медиа; бот о нём не знает |
| Worker конкретного бота | подготовку файла с Яндекс Диска для своей платформы |
| VK / Telegram / Instagram бот | получение своего контента из BotCRM и отправку ответа пользователю |

Токен Directus хранится только в окружении API BotCRM. Каждый бот получает отдельный `BOTCRM_CONTENT_TOKEN`, который не открывает контент других ботов и не даёт доступ к CRM.

## Подключение внутреннего хранилища

### Диск с личными файлами: папка приложения

Используйте OAuth-приложение с единственным правом `cloud_api:disk.app_folder`. Например, приложение `bot_crm` получает собственную папку `Приложения/bot_crm`. Яндекс ограничивает токен этой папкой; остальные файлы аккаунта ему недоступны.

1. Создайте приложение **для доступа к API или отладки** в [Яндекс OAuth](https://oauth.yandex.ru/client/new/), выберите только «Доступ к папке приложения на Диске» и получите токен.
2. Сохраните токен на сервере в файл с правами `600`, вне Git, в формате `CONTENT_PLATFORM_YANDEX_TOKEN=…`.
3. Из корня BotCRM выполните:

   ```sh
   node infra/scripts/configure-yandex.mjs --token-file /private/path/yandex.env --env-file .env.production
   ```

Команда проверит доступ к `app:/` и запрет чтения корня Диска, затем сохранит токен, настоящий путь папки и `CONTENT_PLATFORM_YANDEX_APP_FOLDER_ONLY=true` в окружении. Название системной папки зависит от языка аккаунта; вручную подставлять «Приложения» не нужно. Токен не выводится в терминал.

Новые подключения получают подпапки `<папка приложения>/<slug-бота>`. API создаёт каталоги внутри приложения и не пытается читать его родительские каталоги, к которым ограниченный токен не имеет доступа. CRM хранит полный путь, возвращённый Яндексом из `app:/`, поэтому существующие клиенты скачивания медиа продолжают работать.

Перед переключением существующего подключения скопируйте его файлы в новую подпапку и обновите `bot_content_profiles.yandex_root`, `media_assets.yandex_path` и сохранённые пути превью в истории сообщений. Сохраняйте вложенность и имена; готовые идентификаторы медиа VK/Telegram менять не нужно. Уберите старые пути из `CONTENT_PLATFORM_BINDINGS`, иначе импорт восстановит их. Старые файлы можно оставить на месте. После проверки выкатывайте приложение и обновляйте токен конкретного media worker.

В интерфейсе редактор выбирает файлы из папки своего бота. Личные файлы и каталоги других ботов в этом выборе не показываются.

### Обычная папка Диска

В окружение API добавьте:

```dotenv
CONTENT_PLATFORM_URL=http://directus:8055
CONTENT_PLATFORM_TOKEN=directus-server-token
CONTENT_PLATFORM_YANDEX_TOKEN=yandex-disk-oauth-token
CONTENT_PLATFORM_YANDEX_ROOT=/bot_crm
CONTENT_PLATFORM_NETWORK=bot_platform_backend
CONTENT_PLATFORM_BINDINGS=[{"workspaceId":"00000000-0000-4000-8000-000000000001","botSlug":"vk_test_bot","contentBotKey":"vk-content-bot","label":"VK Content Bot","channel":"vk","yandexRoot":"/VK Content Bot"}]
```

`CONTENT_PLATFORM_BINDINGS` теперь используется только для безопасного первичного импорта старых привязок. После миграции источником истины становится таблица `bot_content_profiles` в PostgreSQL. Новые подключения создают профиль автоматически.

Одна импортируемая запись связывает:

- `workspaceId` — UUID рабочего пространства BotCRM из `GET /api/v1/auth/me`;
- `botSlug` — технический slug бота в BotCRM;
- `contentBotKey` — поле `key` бота в коллекции `content_bots` Directus;
- `label` — понятное название в интерфейсе;
- `channel` — `vk`, `telegram`, `instagram` или `other`.
- `yandexRoot` — нестандартная корневая папка медиатеки; обычно её указывать не требуется.

`CONTENT_PLATFORM_YANDEX_TOKEN` остаётся только на API-сервере. Интерфейс получает список файлов и временные превью, но никогда не получает OAuth-токен.

В production BotCRM обращается к Directus по общей внутренней Docker-сети. Так запросы не выходят в Tailscale Funnel и не зависят от публичного маршрута. `CONTENT_PLATFORM_NETWORK` должна совпадать с именем backend-сети стека Content Platform.

Один workspace не может открыть контент другого, даже если пользователь подставит чужой `botSlug` в запрос вручную.

## Подключение процесса бота

1. Подключите бота в разделе **Боты и каналы**. BotCRM автоматически создаст контентное пространство и подпапку `<CONTENT_PLATFORM_YANDEX_ROOT>/<slug-бота>`. В режиме папки приложения это, например, `Приложения/bot_crm/<slug-бота>`. Существующие привязки сохраняют свой прежний путь и мигрируются отдельно.
2. Откройте **Автоответы**, выберите бота и нажмите **Токен для бота**.
3. Сохраните показанный токен в окружение процесса как `BOTCRM_CONTENT_TOKEN` и укажите `BOTCRM_URL`.
4. Бот обращается только к `/api/v1/bot-content/*`. Токен Directus ему больше не нужен.

Полное значение токена показывается один раз. В PostgreSQL сохраняется только SHA-256-хеш; токен можно отозвать без изменения остальных ботов.

## Работа редактора

1. Откройте **Автоответы** и выберите бота.
2. Нажмите **Новый автоответ**, введите ключевую фразу и текст ответа.
3. Чтобы добавить фото или видео, нажмите **Выбрать с Яндекс Диска** и выберите файл карточкой. Путь вводить не нужно.
4. При желании добавьте кнопки. Технические параметры спрятаны в **Дополнительных настройках**.
5. Проверьте ответ в превью и нажмите **Сохранить**.
6. Во вкладке **Если ничего не найдено** настройте общий запасной ответ.

Операторы могут просматривать настройки. Создавать и изменять контент могут владелец, администратор и супервайзер.

## Отказоустойчивость

- недоступность Content Platform затрагивает только раздел «Автоответы», остальные разделы CRM продолжают работать;
- API ограничивает время внешнего запроса восемью секундами;
- секреты и исходные ошибки Directus не возвращаются в браузер;
- создание ответа выполняется с компенсирующей очисткой, если вложенный блок или кнопка не сохранились;
- удаление правила не удаляет общий ответ, если его использует другое правило.

## Работа с медиатекой

- Файлы выбираются с Яндекс Диска и появляются в медиатеке. Оригинал продолжает храниться на Диске.
- Повторный выбор того же пути на Яндекс Диске использует уже существующую карточку и не создаёт дубликат.
- Корзина убирает карточку только из медиатеки BotCRM — файл на Яндекс Диске не удаляется.
- Материал, который используется в автоответе, защищён от удаления. Сначала открепите его, сохраните автоответ, затем уберите из медиатеки.
- В медиатеке может быть сколько угодно материалов; найти нужный помогает поиск. К одному ответу можно прикрепить не более 10 файлов.
