# Тестовый VK-бот для BotCRM

Этот пример повторяет сценарии Telegram test bot, но работает через официальные сообщения сообщества VK и Bots Long Poll API. Бот получает события у VK, передаёт их в BotCRM и ставит ответы в очередь платформы. Поэтому операторский перехват, история, переменные, рассылки и доставка используют тот же connector, что и остальные функции CRM.

## Что проверяет пример

- создание VK-контакта, identity, диалога и сообщений;
- загрузку имени, города и `photo_200` из профиля VK;
- одинаковые команды `/start`, `/price`, `/buy`, `/support`, `/status`, `/help`;
- пользовательские переменные и автоматизации;
- режимы `BOT`, `HUMAN` и `PAUSED`;
- ответы бота и оператора через официальный `messages.send`;
- идемпотентность событий VK;
- восстановление Bots Long Poll после смены `key` или сервера.

## 1. Создайте и настройте сообщество VK

1. Создайте сообщество либо откройте существующее, которым вы управляете.
2. Откройте «Управление → Сообщения» и включите сообщения сообщества.
3. Откройте «Управление → Работа с API → Ключи доступа».
4. Создайте ключ доступа сообщества с разрешением на сообщения сообщества.
5. Откройте вкладку «Long Poll API», включите его и выберите актуальную версию API.
6. На вкладке типов событий включите минимум «Входящее сообщение» (`message_new`).
7. Скопируйте числовой ID сообщества без минуса. Например, для `club123456` нужен `123456`.

Используйте именно ключ сообщества, а не токен личной страницы. Не отправляйте ключ в чат, не добавляйте его в Git и не показывайте на скриншотах.

## 2. Добавьте настройки в корневой `.env`

Перенесите переменные из `.env.example` этой папки в корневой `.env` проекта:

```env
VK_TEST_BOT_TOKEN=ключ_доступа_сообщества
VK_TEST_GROUP_ID=123456
VK_TEST_API_VERSION=5.199

VK_TEST_BOTCRM_TOKEN=
VK_TEST_BOTCRM_URL=https://botcrm-rpi.tailcc0b45.ts.net
VK_TEST_WORKSPACE_ID=ws_demo
VK_TEST_BOT_SLUG=vk_test_bot

VK_TEST_BOT_PORT=4320
VK_TEST_BOT_CALLBACK_SECRET=
```

Если в корневом `.env` уже задан подходящий `SERVICE_TOKEN`, `VK_TEST_BOTCRM_TOKEN` можно оставить пустым. Иначе создайте отдельный токен в «Настройки → Сервисные токены» и вставьте его в `VK_TEST_BOTCRM_TOKEN`.

В `VK_TEST_BOTCRM_URL` указывается корень сайта без `/api/v1`. Бот может работать на другом компьютере или сервере: ему нужен только исходящий доступ к VK и HTTPS-доступ к BotCRM.

## 3. Создайте подключение в BotCRM

Откройте «Боты и каналы → Подключить бота» и заполните:

| Поле | Значение |
|---|---|
| Канал | `VK Community Messages` |
| Режим | `Mirror / SDK` |
| Название | `VK Test Bot` |
| Slug | `vk_test_bot` |
| Внешний account / community ID | числовой ID сообщества |
| Endpoint событий оператора | оставить пустым |
| Access token | тот же ключ доступа сообщества |

В Mirror-режиме с Bots Long Poll код подтверждения и Callback secret не требуются. Эти поля появляются только для Gateway или если вы вручную зададите endpoint событий оператора.

После сохранения нажмите «Проверить». BotCRM вызовет официальный `groups.getById`; карточка должна перейти в состояние «Подключён».

## 4. Проверьте конфигурацию и запустите

Из корня проекта:

```powershell
npm run testbot:vk:check
npm run testbot:vk
```

Первая команда безопасно проверяет BotCRM API, ключ сообщества и получение Bots Long Poll server. Полные значения секретов в консоль не выводятся. Вторую команду оставьте запущенной.

При успешном старте появятся строки:

```text
VK-бот сообщества «...» подключён
BotCRM bot slug: vk_test_bot
Callback BotCRM отключён: endpoint в режиме Mirror можно оставить пустым
```

## 5. Проверьте сценарии

Откройте сообщения сообщества от обычного аккаунта VK и отправьте:

| Команда | Что появится в BotCRM |
|---|---|
| `/start` | контакт, диалог, `lead_score=20`, `lifecycle=new` |
| `/price` | `lead_score=70`, `topic=pricing`, `requested_plan=pro` |
| `/buy` | `lead_score=95`, `intent=purchase`, горячий лид |
| `/support` | `needs_human=true` и автоматический переход диалога в `HUMAN` |
| `/status` | проверка состояния управления |
| `/help` | список команд |

Обычный текст также попадёт в диалог и получит тестовый ответ. Имя, город и доступный аватар пользователя загрузятся через `users.get`.

## 6. Проверьте операторский перехват

1. Отправьте `/start` и откройте появившийся VK-диалог в BotCRM.
2. Нажмите «Забрать у бота».
3. Отправьте ещё одно сообщение из VK. Оно появится в CRM, но тестовый бот не ответит.
4. Ответьте из панели BotCRM — сообщение придёт пользователю VK через connector.
5. Нажмите «Вернуть боту» и отправьте `/status`. Автоматические ответы возобновятся.

Команда `/support` выполняет пункты передачи оператору автоматически.

## Необязательный callback BotCRM

Для обычной проверки он не нужен. Если вашему коду всё же требуется получать уведомления `control.returned` и события операторских ответов:

1. Сделайте endpoint бота доступным для worker BotCRM.
2. Укажите его в подключении, например `https://vk-bot.example.com/botcrm/events`.
3. Задайте одинаковый секрет в поле подписи подключения и `VK_TEST_BOT_CALLBACK_SECRET`.

Локальный адрес `127.0.0.1:4320` подходит только когда bot и worker действительно находятся в одной сетевой среде. Для бота на другом компьютере используйте HTTPS или оставьте endpoint пустым.

## Диагностика

- `VK groups.getLongPollServer: Access denied` — включите Long Poll API, сообщения сообщества и право сообщений у ключа.
- BotCRM показывает «Требует внимания» — проверьте, что в connector вставлен ключ именно этого сообщества.
- Ответ остаётся `queued` — должен работать worker BotCRM, а connector должен пройти проверку.
- `409 bot_not_in_control` — диалог находится у оператора; это ожидаемая защита.
- События приходят дважды — остановите второй экземпляр тестового бота с тем же сообществом.
- Пользователь не получает сообщение — сначала он должен сам начать диалог с сообществом и не блокировать его сообщения.
- VK или BotCRM недоступны из процесса — при необходимости задайте `HTTPS_PROXY` и корректный `NO_PROXY` в корневом `.env`.

Официальные схемы методов и объектов VK доступны в репозиториях [VKCOM/vk-api-schema](https://github.com/VKCOM/vk-api-schema) и [VKCOM/api-schema-typescript](https://github.com/VKCOM/api-schema-typescript).
