# Тестовый Telegram-бот для BotCRM

Это локальный бот для сквозной проверки BotCRM. Он получает Telegram updates через long polling, передаёт входящие события в BotCRM и отправляет ответы через очередь платформы.

## Что проверяет

- создание Telegram-контакта, identity, диалога и входящего сообщения;
- отображение имени, username, языка и пользовательских переменных;
- исходящую очередь, Telegram delivery и историю сообщений;
- идемпотентность по `telegram:<update_id>`;
- режимы `BOT`, `HUMAN` и `PAUSED`;
- callback от BotCRM с проверкой HMAC-подписи;
- данные для фильтров и CRM-автоматизаций.

## 1. Создание бота в Telegram

1. Откройте [@BotFather](https://t.me/BotFather).
2. Отправьте `/newbot`.
3. Задайте имя и username, оканчивающийся на `bot`.
4. Скопируйте полученный токен.

Токен нельзя отправлять в чат, добавлять в Git или показывать на скриншотах.

## 2. Локальная конфигурация

Перенесите переменные из `.env.example` этой папки в корневой `.env` проекта. Минимально необходимо заполнить:

```env
TELEGRAM_TEST_BOT_TOKEN=токен_от_BotFather
TELEGRAM_TEST_BOT_CALLBACK_SECRET=случайная_строка_не_короче_32_символов
```

По умолчанию используется корневой `SERVICE_TOKEN`. Для более строгой изоляции создайте в BotCRM отдельный сервисный токен и поместите его в `TELEGRAM_TEST_BOTCRM_TOKEN`.

## 3. Подключение в BotCRM

Откройте «Боты и каналы» → «Подключить бота» и укажите:

| Поле | Значение |
|---|---|
| Канал | Telegram Bot API |
| Режим | Mirror — webhook у бота |
| Название | Telegram Test Bot |
| Slug | `telegram_test_bot` |
| Внешний account ID | можно оставить пустым |
| Endpoint событий оператора | `http://127.0.0.1:4310/botcrm/events` |
| Telegram bot token | токен от BotFather |
| Webhook secret token | значение `TELEGRAM_TEST_BOT_CALLBACK_SECRET` |

Slug должен совпадать с `TELEGRAM_TEST_BOT_SLUG`, иначе входящие сообщения не привяжутся к созданному connector.

После сохранения нажмите «Проверить». BotCRM вызовет официальный метод Telegram `getMe`.

## 4. Запуск

Инфраструктура, API, worker и web должны быть запущены. В четвёртом терминале выполните:

```powershell
npm run testbot:telegram
```

Успешный запуск выводит username бота и callback endpoint. Терминал нужно оставить открытым.

## 5. Команды

| Команда | Что появится в CRM |
|---|---|
| `/start` | новый контакт, диалог, `lead_score=20`, `lifecycle=new` |
| `/price` | `lead_score=70`, `topic=pricing`, `requested_plan=pro` |
| `/buy` | `lead_score=95`, `intent=purchase`, горячий лид |
| `/support` | `topic=support`, `priority=normal`, затем автоматическая передача оператору |
| `/status` | пояснение для проверки перехвата |
| `/help` | список команд |

Обычный текст также зеркалируется и получает тестовый ответ.

## 6. Проверка перехвата

Самый быстрый способ — отправить /support: бот сначала пришлёт подтверждение, затем сам переведёт диалог в режим HUMAN. Следующие сообщения сохранятся в CRM без автоматического ответа, пока оператор не нажмёт «Вернуть боту».

1. Напишите боту `/start` — ответ должен появиться и в Telegram, и в «Диалогах».
2. В BotCRM откройте диалог и нажмите «Забрать у бота».
3. Напишите в Telegram ещё одно сообщение. Оно появится в CRM, но бот не ответит.
4. Ответьте из панели — сообщение должно прийти в Telegram.
5. Нажмите «Вернуть боту» и снова отправьте `/status` — автоматический ответ возобновится.

## 7. Проверка воронки и автоматизации

1. Создайте воронку и этапы «Новая заявка», «Квалификация», «Оплата», «Успешно».
2. После `/start` создайте сделку для появившегося контакта.
3. Создайте правило: событие `message.received` → условие `attributes.lead_score >= 90` → действие «Переместить сделку».
4. Отправьте `/buy` и проверьте перемещение карточки.

Если текущий редактор автоматизаций ожидает другое имя поля, используйте `lead_score` или `attributes.lead_score` в зависимости от подсказки в интерфейсе.

## Диагностика

```powershell
npm run testbot:telegram:check
```

Команда проверяет доступность BotCRM API и наличие обязательных переменных, не выводя секреты.

Проверка также вызывает безопасный метод Telegram `getMe`. Если Telegram на компьютере доступен только через VPN или локальный прокси, задайте в корневом `.env` переменные `HTTPS_PROXY` и `NO_PROXY`. BotCRM API, worker и тестовый бот используют их одинаково.

- `409 bot_not_in_control` — диалог забрал оператор; это ожидаемое поведение.
- `Conversation has no channel connector` — slug в панели и `TELEGRAM_TEST_BOT_SLUG` не совпадают либо сообщение отправлено до создания connector; отправьте новое сообщение после настройки.
- `Conflict: terminated by other getUpdates request` — этот же Telegram-токен запущен ещё в одном long-polling процессе.
- Ответ остаётся `queued` — убедитесь, что запущен `npm run worker:dev` и connector успешно прошёл проверку.
- Callback не приходит — endpoint должен быть `http://127.0.0.1:4310/botcrm/events`, а секреты должны полностью совпадать.
