# Работа с BotCRM

## GitHub Releases

Всегда оформлять релизы по образцу [BotCRM v0.4.3](https://github.com/Evgenykravchenko/botcrm/releases/tag/v0.4.3).

- Тег: `v<SemVer>`. Название: `BotCRM v<SemVer>`.
- Описание: короткий вводный абзац, конкретные изменения списком, фактические результаты проверок, ссылка на инструкцию в выпущенном теге, номера PR.
- Брать структуру из [.github/RELEASE_TEMPLATE.md](.github/RELEASE_TEMPLATE.md). Не заменять её автоматически сгенерированными заметками или одной строкой.
- Не писать, что выкатка или проверки прошли, пока это не подтверждено. После проверки production дополнять описание результатом выкатки.
- Версии корневого package.json, workspaces, package-lock.json и CHANGELOG должны соответствовать тегу.
- Соблюдать защиту main: отдельная ветка, Conventional Commits, PR и обязательные проверки. Публиковать релиз из проверенного коммита main.

## Production

Использовать штатную blue/green-выкатку из docs/SAFE_DEPLOY.md. Сохранять предыдущий слот для отката. Не менять чужие проекты, тома, секреты или состояние Tailscale.
