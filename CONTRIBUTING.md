# Как помочь BotCRM

Спасибо за интерес к проекту. Перед изменениями создайте issue или обсудите крупную идею, чтобы работа не дублировалась.

## Подготовка окружения

Требуются Node.js 22+, npm и Docker с Compose plugin.

```bash
npm ci
cp .env.example .env
npm run infra:up
node infra/scripts/migrate.mjs
```

Для разработки web, API и worker запускаются в отдельных терминалах:

```bash
npm run dev
npm run api:dev
npm run worker:dev
```

## Ветки и коммиты

- Создавайте отдельную ветку от `main`: `feat/...`, `fix/...`, `docs/...`, `security/...`.
- Один pull request должен решать одну задачу.
- Не добавляйте `.env`, токены, production-дампы, логи и реальные персональные данные.
- Текст коммита должен кратко описывать результат, например `fix: prevent duplicate campaign delivery`.

## Перед pull request

```bash
npm run lint
npm run test:all
npm run api:build
npm run worker:build
npm run build --workspace @botcrm/sdk
```

Если менялась схема PostgreSQL, добавьте миграцию в `infra/migrations/` и проверьте обновление как новой, так и существующей базы. Если меняется публичный API, обновите OpenAPI, SDK, `/docs` и `docs/DEVELOPER_GUIDE.md`.

## Требования к изменениям

- Сохраняйте изоляцию данных по `workspace_id`.
- Все операции записи должны проверять роль и workspace на backend.
- Повторяемые события и отправки должны оставаться идемпотентными.
- Секреты нельзя выводить в UI, audit и application logs.
- Используйте только официальные API каналов.
- Для пользовательских изменений добавляйте понятные пустые, loading и error-состояния.
- Новое поведение должно иметь тест либо объяснение, почему автоматический тест неприменим.

## Pull request

Заполните шаблон: цель, способ проверки, влияние на миграции/безопасность и скриншоты интерфейса. Отправляя вклад, вы подтверждаете, что имеете право предоставить код на условиях лицензии проекта.

Уязвимости не публикуйте в issue — следуйте [политике безопасности](SECURITY.md).
